# Provisioning reference — flows and endpoints, as configured

> Generated by `scripts/build-provisioning-reference.mjs`. Do not edit by hand — run
> `npm run provisioning`. `npm test` fails if any page here has drifted from the
> packages it was read from.

## What this is

The configuration of every flow and every endpoint across both platforms, read out of
the packages in this repository and printed as those packages carry it. For each flow:
its identity, definition envelope and parameters, the connections its actions are bound
to, its trigger — method, path, authentication posture and full request schema — every
response it returns with status code, headers and body, its termination and error
handling, every variable and initial value, every SharePoint operation and outbound HTTP
call, the full dependency graph, and the configured input of every action, verbatim.

## What this is not

It is not an account of what the flows are *for*. A definition cannot state its own
purpose, and a purpose invented here would read as knowledge. Where a register attributes
a flow to a contract key or a portal endpoint, that attribution is cited and named as
such; where nothing does, nothing is said.

It is also not [`../FLOW_CATALOGUE.md`](../FLOW_CATALOGUE.md), which remains the place to
go for a flow's shape at a glance — what triggers it, what it touches, how it scores
against the build standard, and its action tree. This reference answers the next
question: what is that action actually configured with.

from, in its own first line.

  search across every flow at once (by contract key, action name, connection, or the
  SharePoint list a call targets), filter to the set you mean, and jump to a section or
  to one action out of 252. No server and no build step — open the file. The pages below
  remain the record a git history shows.

  platforms: contract keys and what the applications send, the flow behind each key, the
